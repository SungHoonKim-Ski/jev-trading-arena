# Jev 트레이딩 아레나

TypeSafe의 판단 전용 모델 **Jev**에게 매매 판단을 맡겨 한국·미국 주식과 코인을 모의 매매하는 서비스입니다.
기간, 종목, Jev에게 묻는 방식(전략), effort, 매매 주기를 정하면 과거 시세로 백테스트를 돌립니다.
결과는 DB에 쌓이고 **랭킹**과 **전략 분석**으로 누가 어떤 조합으로 가장 많이 벌었는지 보여 줍니다.

**바로 써 보기**: https://jev-trading-arena.vercel.app

## 문제 이해: 누구의 어떤 불편을 해결하나

- **대상**: LLM이나 판단 모델로 투자 전략을 실험해 보고 싶은 개인 투자자와 개발자.
- **불편 1**: "AI에게 사라/팔라고 물으면 돈이 될까?"를 확인하려면 시세 수집, 지표 계산, 프롬프트 설계, 모델 호출, 백테스트 엔진, 수익률 계산을 모두 직접 만들어야 합니다.
- **불편 2**: 같은 모델이라도 묻는 방식이 결과를 바꿉니다. 예/아니오로 물을지, 확률분포를 쓸지, 등급으로 받을지에 따라 다릅니다. 얼마나 자주 사고팔지도 결과를 바꿉니다. 이것을 공정하게 비교할 도구가 없습니다.
- **불편 3**: 혼자 돌린 결과는 기준점이 없습니다. 같은 기간에 남들은 어떤 설정으로 얼마를 벌었는지, 그냥 사서 들고 있었으면 얼마였는지와 비교해야 의미가 생깁니다.
- **흔한 함정**: 모델이 과거 주가를 기억해서 미래를 "커닝"하는 문제, 당일 종가를 보고 당일 종가에 사는 룩어헤드 문제가 있습니다. 직접 만들면 놓치기 쉽습니다.

## 해결의 효용: 기존 번거로움을 얼마나 줄이나

| 기존에 직접 해야 하던 일 | 이 서비스에서는 |
|---|---|
| 시세 API 연동, 수정주가 처리, 한국·미국 거래일 달력, 24시간 코인 시장 | 종목 코드나 코인 심볼만 입력하면 자동 수집 후 DB 캐시 |
| 지표 계산 후 모델이 이해할 문장으로 변환 | effort별로 자동 생성 (숫자는 코드가 계산, Jev에는 의미 라벨만 전달) |
| Jev 질문 설계, 응답 해석, 재시도, 비용 계산 | "오를까?" 질문과 확신 기준 6단계 × effort 3단계가 내장, 동일 요청은 캐시로 재호출 없음 |
| 룩어헤드·암기 편향 방지 | 종가에 판단하고 다음 거래일에 체결, 종목명·날짜는 익명화 |
| 조합 비교를 위한 반복 실행 | 체크박스로 최대 24개 조합을 한 번에 실행하고 진행률 표시 |
| 결과 정리, 비교 기준 설정 | 매수 후 보유, 시장 지수(KOSPI, S&P 500, 코인은 비트코인) 대비 초과수익을 자동 계산 |
| 다른 사람 결과와 비교 | 랭킹(사용자별 최고 기록, 기간 필터)과 전략×effort, 전략×주기 히트맵 |

실험 하나에 들던 준비가 며칠 분량의 코드 작성에서 폼 입력과 클릭 한 번으로 줄어듭니다.

## 사용 편의성: 준비 없이 쓸 수 있나

- **설치 한 번**: Node.js 22.18 이상에서 `npm install` 후 `npm start`로 끝납니다. 별도 DB 서버가 필요 없습니다(SQLite 파일 자동 생성).
- **설치 없이 웹으로**: Vercel에 배포돼 있어 브라우저만 있으면 됩니다.
- **API 키 없이도 동작**: TypeSafe 키가 없으면 Mock 엔진으로 전체 흐름을 체험할 수 있습니다. 키를 넣으면 실제 Jev로 바뀝니다. 두 결과는 랭킹에서 분리됩니다.
- **고를 것이 네 가지뿐**: 시장, 종목 하나(대표 개별 종목 또는 ETF, 코인은 5종), 기간, 그리고 "오를 확률이 몇 % 이상이면 살까?"를 라디오로 고릅니다. 종목코드를 직접 입력하지 않습니다. 시장별 기본 자본금과 수수료·세금은 미리 설정돼 있습니다.
- **반복 조작 없음**: 여러 전략을 한 번에 실행합니다. 결과는 실시간으로 갱신되고, 닉네임은 브라우저에 기억됩니다. 분봉은 서버가 알아서 주기적으로 수집합니다.
- **한국어 안내**: 입력 오류는 "종료일은 오늘 이전이어야 합니다"처럼 한국어로 바로 알려 줍니다.

```bash

npm start                                  # http://localhost:3000
TYPESAFE_API_KEY=... npm start             # 실제 Jev 사용
```

| `JEV_MODEL` | `jev-latest` | 결과 재현이 필요하면 `jev-1.13.0`처럼 버전 고정 |
| `PORT` | `3000` | |
| `DB_PATH` | `data/trading.db` | |
| `INTRADAY_COLLECT` | 켜짐 | `off`면 분봉 주기 수집 중지 |

| `TRUST_PROXY` | 꺼짐 | 프록시 뒤에서만 `1`. 켜야 `X-Forwarded-For`로 요청 제한을 셉니다 (Vercel은 자동) |

## 배포

```
브라우저 ──▶ Vercel ─┬─ 정적 화면 (public/)
                    └─ 서버리스 함수 (/api/*, 서울 icn1) ──▶ Turso (libSQL, 원격 SQLite)
                         └ 일일 크론: 분봉 수집 + 멈춘 실행 복구
```

- **Vercel**: `npm run build:vercel`이 Build Output API 산출물(화면 + API 함수 + 크론)을 만듭니다. 바이낸스 API가 미국 IP를 막기 때문에 함수는 서울(icn1) 리전에서 실행합니다. 원본 틱 저장소는 로컬 전용이라 배포 환경에서는 틱 체결이 꺼집니다. 백테스트는 응답 후 `waitUntil`로 끝까지 실행합니다. 함수가 시간 초과로 끊긴 실행은 크론이 다시 돌립니다.
- **자동 배포**: GitHub 저장소가 Vercel 프로젝트에 연결돼 있습니다. `main`에 푸시하거나 병합하면 프로덕션에, PR 브랜치에 푸시하면 미리보기 주소에 자동으로 배포됩니다. 미리보기도 같은 Turso DB를 쓰므로 PR 미리보기에서 만든 실행 기록은 운영 랭킹에 함께 보입니다.
- **DB**: 로컬은 SQLite 파일, 배포는 Turso를 씁니다. SQL과 코드는 같습니다(`@libsql/client`).

Vercel 프로젝트 환경 변수:

| 이름 | 설명 |
|---|---|
| `TURSO_DATABASE_URL` | `libsql://<db>-<org>.turso.io` |
| `TURSO_AUTH_TOKEN` | Turso DB 토큰 |
| `CRON_SECRET` | 크론 호출 인증용 임의 문자열 (Vercel이 자동으로 헤더에 넣음) |
| `TYPESAFE_API_KEY` | 선택. 있으면 실제 Jev 사용 |
| `ALLOWED_ORIGINS` | 선택. 기본 `*`. 운영은 `https://jev-trading-arena.vercel.app`으로 제한 |

처음 한 번 설정한 뒤에는 `main`에 병합하는 것으로 배포가 끝납니다. 새 환경에서 처음 설정할 때만 아래를 실행합니다.

```bash
npx vercel login
npx vercel link --yes --project jev-trading-arena          # 저장소 연결과 자동 배포 설정 포함
npx vercel integration add tursocloud/database             # Turso DB 생성, 환경 변수 자동 등록
npx vercel env add CRON_SECRET production                  # 임의의 긴 문자열
npx vercel deploy --prod                                   # 수동 배포가 필요할 때만
```

## 핵심 개념

**Jev에게 묻는 방식: "오를까?" + 확신 기준**

Jev에게는 종목마다 "앞으로 오를까?"라는 예/아니오 질문(Noul) 하나만 합니다. Jev는 예일 확률을 0~1 사이 숫자로 돌려줍니다. 사용자는 "오를 확률이 몇 % 이상이면 살까?"만 정합니다. 선택지는 95%, 90%, 85%, 80%, 75%, 70%이고 기본값은 80%입니다.

| 매도 규칙 | 동작 | 특징 |
|---|---|---|
| 반대 확신 매도 (기본) | 내릴 확률(1 − 오를 확률)이 기준 이상일 때만 판다. 그 사이는 보유 유지 | 거래가 적고 수수료가 덜 든다 |
| 확신 떨어지면 즉시 매도 (고급 설정) | 오를 확률이 기준 밑으로 내려가면 바로 판다 | 높은 기준에서는 샀다 팔았다를 반복하기 쉽다 |

기준이 높을수록 거래가 드물어집니다. 95%를 고르면 기간 내내 한 번도 사지 않을 수 있습니다.

이전에 제공하던 3지선다(단호하게, 확률대로)와 5단계 등급 방식은 새 실행에서 뺐습니다. 이미 쌓인 기록은 랭킹에 "이전 방식"으로 표시되고, 전략 분석 집계에서는 제외됩니다. 확신 기준 도입 전의 "오를까?" 실행은 "이전 규칙"으로 따로 묶입니다.

**effort**: Jev API에는 effort 파라미터가 없습니다. 그래서 이 서비스는 effort를 "얼마나 공들여 묻는가"로 정의했습니다.

| effort | state(입력) | 질문 | 추가 장치 |
|---|---|---|---|
| Low | 지표 2개 | 관점 1개 | |
| Medium | 지표 7개 | 관점 2개 앙상블 | |
| High | 지표 9개 + 최근 10일 일별 흐름 | 관점 3개 앙상블 | 신뢰도 0.35 미만이면 행동 보류 |

**매매 주기**는 매일, 매주, 격주, 매월 중에서 고릅니다. 주식은 1/5/10/21거래일, 코인은 1/7/14/30일입니다. 비중 변화가 10%p 미만이면 거래하지 않습니다.

**시장별 차이**

| 시장 | 심볼 예 | 거래일 | 연환산 | 최소 수량 | 수수료(매수/매도) | 벤치마크 지수 |
|---|---|---|---|---|---|---|
| 한국 | `005930` | 평일 | 252일 | 1주 | 0.015% / 0.215%(거래세 포함) | KOSPI |
| 미국 | `AAPL` | 평일 | 252일 | 1주 | 0% / 0% | S&P 500 |
| 코인 | `BTC`, `ETH`, `SOL`, `XRP`, `BNB` | 매일(UTC 0시 기준) | 365일 | 0.00000001개 | 0.1% / 0.1% | 비트코인 |

코인은 바이낸스 USDT 마켓의 대표 5종만 제공합니다(1 USDT ≈ 1 USD로 표시). Jev에게는 "this cryptocurrency", "the next 7 days"처럼 코인에 맞는 문구로 묻습니다.

**체결 방식**은 세 가지입니다.

| 방식 | 대상 | 체결가 |
|---|---|---|
| 시가 | 전체 | 다음 거래일 시가 |
| 분봉 VWAP | 전체 | 다음 거래일 분봉의 거래량가중평균가 (주식은 수집된 분봉, 코인은 바이낸스 1분봉) |
| 원본 틱 | 코인, 로컬 서버 | 다음 날 0시부터 실제 체결을 순서대로 따라가며, 시장 체결량의 10%(`TICK_PARTICIPATION`)만 내 주문이 가져간다고 보고 계산 |

틱이 없으면 1분봉, 1분봉도 없으면 일봉 평균가로 대체하고, 결과에 출처별 체결 건수를 남깁니다.

## 데이터

- **일봉**: Yahoo Finance 수정주가. 요청 구간이 DB에 있으면 재사용합니다.
- **분봉**: 무료 소스는 과거 틱 데이터를 제공하지 않습니다. Yahoo 분봉도 1분봉 30일, 5분봉 60일, 60분봉 730일까지만 줍니다. 그래서 서버가 주기적으로 받아 DB에 계속 누적합니다. 서비스를 오래 켜 둘수록 1분봉 기간이 길어집니다.
- **코인 시세**: 일봉과 1분봉은 바이낸스 API에서 받습니다. 1분봉은 상장 이후 전체 이력이 있어서, 체결일마다 그날 치만 받아 DB에 저장합니다.
- **코인 원본 틱**: 바이낸스 공개 데이터(data.binance.vision)의 일별 체결 파일을 SHA-256 체크섬으로 검증한 뒤 로컬 DuckDB(`data/ticks.duckdb`)에 저장합니다. 하루 비트코인 약 330만 건(약 37MB), 5종 합계 약 120MB입니다. 서버가 매일 전날 치를 자동 수집하고, 틱 체결 백테스트는 필요한 날을 자동으로 받습니다. `TICK_STORE_MAX_GB`(기본 10GB)를 넘으면 수집을 멈추고 1분봉 체결로 대체합니다. 용량은 다운로드 전에 확인하므로 최대 하루치만큼 넘을 수 있습니다. 틱 체결 백테스트는 시작 전에 새로 받을 틱 용량을 추정해, 남은 용량을 넘으면 실행하지 않고 안내합니다.

```bash
npm run ticks -- ALL 2026-09-01 2026-09-23   # 5종 전체
npm run ticks -- BTC,ETH 2026-09-20          # 하루치
```

DuckDB 파일은 한 프로세스만 열 수 있습니다. 서버가 켜져 있으면 CLI는 자동으로 서버 API를 통해 하루씩 수집합니다.

| 틱 관련 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `TICKS` | 켜짐 | `off`면 원본 틱 저장소와 틱 체결 비활성 |
| `TICK_STORE_PATH` | `data/ticks.duckdb` | |
| `TICK_STORE_MAX_GB` | `10` | 틱 저장소 용량 상한 |
| `TICK_PARTICIPATION` | `0.1` | 틱 체결 시 시장 체결량 대비 내 주문 비율 |
| `TICK_DAILY_COLLECT` | 켜짐 | `off`면 매일 전날 틱 자동 수집 중지 |
- **VWAP 환산**: 분봉은 원주가이고 일봉은 수정주가입니다. 그래서 수정 시가 × (분봉 VWAP ÷ 첫 분봉 시가)로 환산합니다. 분봉이 없는 날은 일봉 (시가+고가+저가+종가)/4로 대체하고, 대체 횟수를 결과에 표시합니다.
- **수동 수집**: 화면의 "데이터" 탭을 쓰거나 아래 명령을 실행합니다. cron에 등록해 두면 좋습니다.

```bash
npm run collect                       # 추적 중인 모든 종목
npm run collect -- KR 005930 000660
npm run collect -- US AAPL NVDA
```

## 구조

```
src/
  market/     시세 수집(yahoo, intraday), 지표→라벨 변환(features), DB 캐시(priceService), 분봉 수집기
  jev/        TypeSafe HTTP 클라이언트(재시도·검증), Mock, 캐시, 질문 생성, 응답 해석
  backtest/   순수 시뮬레이션 엔진, 성과 지표, 실행기, 동시 실행 제한 대기열
  db/         libSQL 스키마·마이그레이션, 로컬/원격 연결, 저장소(시세·분봉·실행·Jev 캐시)
  api/        라우터, zod 입력 검증, 레이트리밋, CORS, 정적 파일
  vercel/     서버리스 진입점 (Turso 연결, waitUntil)
  ticks/      코인 원본 틱 저장소 (DuckDB), 바이낸스 틱 파일 다운로더
public/       바닐라 JS 화면 (실행, 랭킹, 전략 분석, 내 기록, 데이터, 상세)
test/         단위·통합 테스트 (node:test)
e2e/          Playwright E2E (가짜 시세 서버 사용)
```

| 메서드 | 경로 | 설명 |

## 한계와 주의

- **Mock 엔진은 Jev가 아닙니다.** 같은 입력 라벨을 보고 규칙으로 답하는 대체물입니다. 실제 Jev 성능을 말하려면 `engine=live` 결과만 보세요.
- **Jev는 영어가 주 언어입니다.** 그래서 state와 질문은 영어로 보냅니다. 수치 계산은 Jev 대신 코드에서 합니다(Jev 1.13 jaggedness 문서 권고).
- **거래 비용은 단순화했습니다.** 한국은 매수 0.015%, 매도 0.015%와 거래세 0.2%로, 미국은 0%로 가정합니다. 슬리피지는 VWAP 체결로만 근사합니다.
- **수정주가 기준**이며 배당 재투자 효과가 가격에 포함됩니다. 벤치마크는 소수점 주식, 수수료 없는 동일비중 보유입니다.
- **과거 성과는 미래 수익을 보장하지 않습니다.** 이 서비스는 모의 실험 도구이며 투자 권유가 아닙니다.
